# Koin OpenHarmony 接入指南

2026-10-08 的 Core/CMP/Kuikly 消费映射、候选修复和未验收范围见[功能与平台差异](功能与平台差异.md)；下文已有 tag 的验收保留为历史事实，候选修改尚未发布。

基础仓库和依赖配置见 [README](../README.md#安装)。`commonMain` 沿用 `org.koin` API；Android 使用 JVM 变体，iOS/OHOS 使用 Native 变体。

## 与官方 Koin Compose 同用

本 fork 只发布 Core。Android/iOS 若使用官方 `koin-compose:4.1.1` 或 `koin-compose-viewmodel:4.1.1`，在消费模块的 `build.gradle.kts` 中替换它们传递引入的官方 Core 和 Stately：

```kotlin
configurations.configureEach {
    resolutionStrategy.dependencySubstitution {
        substitute(module("io.insert-koin:koin-core"))
            .using(module("com.github.gycrosskit.koin-ohos:koin-core:4.1.1-ohos-2.2.21-7"))
        listOf("stately-strict", "stately-concurrency", "stately-concurrent-collections").forEach { name ->
            substitute(module("co.touchlab:$name"))
                .using(module("com.github.gycrosskit.stately-ohos:$name:2.1.0-ohos-2.2.21-11"))
        }
    }
}
```

发布版保留上游 `io.insert-koin` / `co.touchlab` KLIB 身份，使官方 Native 依赖能匹配；同一个二进制中仍只能解析到一份 Core 和每个 Stately 模块。不要同时直接依赖官方坐标和 fork 坐标。此替换不会为官方 Compose 模块增加 `ohosArm64` 支持，也不提供 Kuikly ViewModel 生命周期接入。

## 状态与生命周期

`koinApplication { ... }` 创建独立容器；由持有它的宿主管理生命周期，并在所有调用结束后执行 `close()`。需要上游全局上下文时可使用 `startKoin` / `stopKoin`；不要在每次 Compose 重组时重复启动容器。
